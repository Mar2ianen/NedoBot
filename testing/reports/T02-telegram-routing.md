# T02 — Telegram Updates, dptree routing, commands and entities

**Base:** T01 branch `codex/testing-t01-quality`, head `41e3e841d13edab24e4a06e7794dc8db79cfc17e`.

## Invariants and counterexamples

| Invariant | Minimal synthetic counterexample / oracle | Defect the test detects |
|---|---|---|
| A recognized command reaches the command handler once; plain and unknown-command text reaches message handling. | Parsed synthetic `/ping`, `/not_a_command arg`, and `hello`; route endpoints return distinct typed tags through `Handler::dispatch`. | Remove `.filter_command::<Command>()`, reverse command/message precedence, or send a command to both handlers. `/ping` will select `Message` or the wrong tag. |
| Updates for edits, reactions, callback queries, member changes, and unsupported update kinds do not alias another route. | V2 schema-valid JSON for each type is decoded by the pinned teloxide `Update` type, then dispatched through the production tree. Unsupported `poll` returns `Continue` with no endpoint tag. | Replace or remove a matching `Update::filter_*` branch, or route an unsupported update to a side-effect endpoint. |
| UTF-16 entity spans map only to Unicode scalar boundaries. | Text `😀x`: `(offset=0,length=2)` maps to `0..4`; `(1,1)` splits the surrogate pair and must be rejected. | Treat Telegram UTF-16 offsets as UTF-8 bytes or scalar indexes, or accept a span in the middle of a supplementary character. |
| Feature-gated commands exist only when the feature is built. | Golden parsing table for always-on commands and positive/negative cases for ask, moderation, manual moderation, voice, and auto-comment. | Remove a command, rename it accidentally, or expose a gated command in a no-default build. |
| Unsupported callbacks are answered exactly once. | Synthetic callback ID sent to a local HTTP Telegram fake; the fake observes one `AnswerCallbackQuery` request. | Return early without answering (spinner remains active), or answer twice. |

The routing tests use the same `update_handler_tree!` macro as production; only endpoint functions are replaced with local tag-returning probes. The independently expected tag table is in the tests and does not call the production handler to decide the expected result. The fake Telegram endpoint is bound to localhost and uses only a synthetic token and callback ID.

The 192-case property uses structurally valid typed Telegram messages generated by the T01 schema-valid strategy, with a fixed seed (`0x54454c454752414d` by default). Set `NEDOBOT_PROPTEST_SEED` to replay another unsigned decimal seed. Proptest shrinking remains enabled. Each property failure prints the minimized case, case ID, seed, SHA marker, and replay command. The replayer accepts only the static case ID `telegram-route-command-precedence` and validates the seed.

## Confirmed correction

Unsupported callback data previously returned without calling Telegram's `answerCallbackQuery`. The handler now routes that fallback through `answer_unsupported_callback`; the localhost fake test verifies one request. This is an isolated behavior correction; command policy, moderation scoring, and sanctions are unchanged.

## Scope and evidence limits

All Update payloads here are V2 unless directly derived from documented Bot API schema. Schema deserialization does not prove every field combination can reach Telegram. There are no private or production fixtures, no live Bot API calls, no production DB, and no external model/API requests. T02 tests route selection and callback acknowledgment; database authorization, scope guards, and duplicate persistence must be established by the relevant handler/SQL tests in T03 and later.
