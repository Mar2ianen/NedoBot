# T02 — Two-chat historical URL corpus

Status: implementation complete; awaiting CI on the focused PR.

## Scope and provenance

The opt-in extractor reads the configured NedoNews and PVO PostgreSQL databases over separate SSH source configurations, forces PostgreSQL read-only mode, verifies each database's `mcp_private.instance_scope`, and exports only link-bearing messages in that configured discussion scope. It does not call Telegram or visit URLs. The raw, private exports and manifests were written outside the repository under a `0700` directory with `0600` files. The script now unlinks registered raw message/QR intermediates in a `finally` block after manifest generation or on failure; only the curated manifest and aggregate summary remain.

The manifest contains canonical URL identity, message ID, observed time, URL class, extraction source, label provenance, validity class, evidence source, parser revision, and explicit assumptions. The historical row does not retain whether it was first ingested from a Bot API update or imported from a Telegram Desktop export, so that limitation is recorded rather than guessed; the Bot API version is likewise unavailable. Message IDs and canonical URLs remain private. No user IDs, message text, or actual URLs are included in this report or committed files. There were no message-level labels joined; all records say `unlabeled_no_message_level_label_joined`.

## Corpus validity

- V1 observed: 19,903 URL records across separately configured production databases. Source rows are persisted Telegram message records; the Bot API version was not stored with those rows.
- V2 synthetic: 3 hand-authored public fixtures using synthetic instances and approved example hosts.
- V3 invalid: 2 fail-closed unit cases (malformed QR digest and unknown instance scope).

The public-corpus validator allows only declared fields and synthetic instance names, restricts URL hosts, and rejects token-shaped strings and long numeric identities. Negative tests exercise those rejection paths. Human review is still required before adding future examples.

## Verification

The unit parser covers visible URLs, hidden Telegram text-link targets, UTF-16 entity offsets, formatted text arrays, rich-message link blocks, QR hash-only evidence, deduplication, cross-instance overlap, and invalid inputs. The PostgreSQL integration test creates fixtures in two separate disposable databases, inserts disjoint scoped and foreign-chat messages, extracts each database independently, and asserts no cross-database or foreign-chat URL appears. It performs no network requests.

The integration test is explicitly run in CI against two dedicated synthetic PostgreSQL databases. The normal workspace test lane compiles the test but does not run ignored PostgreSQL integration cases.

## Operational invocation

After confirming read-only authorization, run from the repository root:

```sh
NEDOBOT_PRIVATE_CORPUS_APPROVED=YES \
  python3 scripts/extract_private_url_history.py \
  --authorized-read-only \
  --output-dir /private/path/outside/the/repository
```

The script uses the configured SSH alias and each instance's `.env` `DATABASE_URL`. It rejects output paths inside the checkout, checks restrictive file modes, and prints aggregate counts only. Treat the private output directory as sensitive; remove it according to the operator's retention policy after analysis. Do not upload it as a CI artifact or add it to Git.

## Remaining limits

- The current production databases have no QR evidence table, so historical QR hashes are unavailable.
- Existing spam flags and user-level moderation labels are not message-level ground truth and were not joined.
- The production `telegram_messages` rows do not retain the Bot API version for historical ingestion.
- No URL was fetched or checked for current liveness; the corpus represents observed stored targets, not reachable destinations.
