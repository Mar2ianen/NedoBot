# T02 — Two-chat historical URL corpus

Status: implementation complete; awaiting CI on the focused PR.

## Scope and provenance

This implementation uses only synthetic JSONL fixtures and two explicitly disposable PostgreSQL databases. No production database, Telegram chat, private message corpus, external URL, or LLM was accessed. There is no SSH extraction command or production database default in this testing pack.

The retained Rust library is exercised with generated synthetic records. The ignored integration test creates temporary tables in two separate synthetic test databases, inserts disjoint scoped messages, and asserts that each extraction includes only its own scope. Public fixtures use synthetic instance names and reserved example hosts.

## Verification

The unit parser covers visible URLs, hidden Telegram text-link targets, UTF-16 entity offsets, formatted text arrays, rich-message link blocks, QR hash-only evidence, deduplication, cross-instance overlap, and invalid inputs. The PostgreSQL integration test creates fixtures in two separate disposable databases, inserts disjoint scoped and foreign-chat messages, extracts each database independently, and asserts no cross-database or foreign-chat URL appears. It performs no network requests.

The integration test is explicitly run in CI against two dedicated synthetic PostgreSQL databases. The normal workspace test lane compiles the test but does not run ignored PostgreSQL integration cases.

## Running the synthetic test

Set `TEST_PRIVATE_HISTORY_DATABASE_URL_A` and `TEST_PRIVATE_HISTORY_DATABASE_URL_B` to two disposable PostgreSQL databases, then run:

```sh
cargo test --test private_url_history two_synthetic_databases_extract_only_their_scoped_messages_and_qr_hashes -- --ignored --exact
```

Do not point these variables at production databases. The test creates temporary tables and writes synthetic rows.
