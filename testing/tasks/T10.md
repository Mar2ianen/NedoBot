# T10 — QR job leases, retries and stale state under faults

**Репозиторий:** NedoBot. **Зависимость:** T09. **Тип:** implementation + actual tests, не просто план.

## Interleavings
- Two workers race `claim_next_qr_scan_job`, expired lease, 5 retries, lease generation mismatch, edit replaces media, deleted message, retry of completed job, QR scan completes after changed message, PG commit fails.
- Inject retryable errors at job acquisition, `replace_qr_evidence_for_job`, `finish_qr_scan_job`, and `refresh_url_shadow_observation_from_links`.
## Properties
- Only current lease/current media is permitted to persist evidence; old lease cannot successfully finish new generation.
- Refresh failure eventually reconciled; no permanent stale positive shadow after edit/remove; no unbounded retry storm, consistent job status.
## Acceptance
- Deterministic scheduled multi-worker integration tests on temporary PG with exact observed state and a bounded clock/timeout.
- Regression for «QR saved, shadow refresh failed» and «edit then old completion», with actual nonzero CI tests.
