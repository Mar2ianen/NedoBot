# T08 — URL export confidentiality, identity and label attribution

**Репозиторий:** NedoBot. **Зависимость:** T07. **Тип:** implementation + actual tests, не просто план.

**Перед стартом:** прочитать актуальный `AGENTS.md` и соответствующий production/test код, `testing/references/INVARIANTS.md`, `testing/references/VALIDITY_LEVELS.md`, `testing/references/CORPUS_PRIVACY.md`. Начинать от свежего `main`, не использовать старые PR head. Работать офлайн на синтетике и тестовых БД.

## Cases
- Short sensitive path token `/r/abc`, arbitrary deeply nested path, query/fragment/userinfo, Telegram invites, BotStart payload, Percent-encoded paths, two query variants of same redacted display URL.
- `--show-paths` opt-in risk, atomic temporary writes, abrupt limit exhaustion, failed fsync/rename simulated, replacement of existing file.
- Current `is_spammer`, latest `owner_review`/`owner_manual`, historical `legacy_backfill`, system events, human `not_spam` overwriting human `spam`.
## Properties
- Default export never leaks any non-root path/query/fragment/userinfo/auth/invite. Full URL identity distinct despite same redacted view.
- Failed export preserves previous file and doesn't silently truncate; 0600 output. Public corpus uses HMAC/pseudonyms only when appropriate.
- Machine and human decisions disjoint; historic `legacy_backfill` not counted as verified manual event.
## Acceptance
- End-to-end synthetic PG export with multiple authors/labels and checks for exact counts; no private URL strings in artifacts or failure logs.
- Include tests for both default and opt-in flags, preserve privacy warning in docs.
