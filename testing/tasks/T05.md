# T05 — UTF-16 Telegram entities, captions and RichMessage

**Репозиторий:** teloxide-antispam + NedoBot. **Зависимость:** T04. **Тип:** implementation + actual tests, не просто план.

**Перед стартом:** прочитать актуальный `AGENTS.md` и соответствующий production/test код, `testing/references/INVARIANTS.md`, `testing/references/VALIDITY_LEVELS.md`, `testing/references/CORPUS_PRIVACY.md`. Начинать от свежего `main`, не использовать старые PR head. Работать офлайн на синтетике и тестовых БД.

## Cases
- `MessageEntity` offsets/lengths in UTF-16 code units, not Rust bytes/chars; emoji before or inside entities, ZWJ family emoji, combining marks, custom emoji, nested/adjacent entities, caption entities.
- Visible URLs, `text_link` hidden URL, `text_mention` numeric User ID, URL buttons and inline markup; invalid offset or split-surrogate V3 lane.
- Fully synthetic Telegram `Message` fixtures, not production copied message JSON.
## Properties
- Correct target identity, type, source provenance, stable extraction order and dedup; hidden URL cannot become visible label.
- Parsing invalid offsets must fail safely, never panic or misattribute UserId. Source-specific transforms do not alter identity.
- HTML escaping / SQL bind boundaries preserved when extracted text is rendered or stored.
## Acceptance
- Structured non-BMP cases with hand-computed independent UTF-16 spans; direct `teloxide-url` tests and at least one NedoBot adapter integration.
- V1/V2/V3 documented; invalid-offset tests never claimed Telegram-valid.

2. Оформить V1/V2/V3 для новых входов, оценить генерацию/отказы, сохранить воспроизводимый seed или минимальный trace.
3. Выполнить применимые `cargo fmt`, `cargo test`, `cargo check`, Clippy, feature matrix и интеграции с **ненулевым** числом тестов; для изменённых исполняемых путей показать доказательство из CI.
4. Не делать production deploy, Telegram API actions, изменения enforcement и работу с закрытым корпусом без доступа. Никаких сырых приватных данных в diff/логах/артефактах.
5. Написать `T05` completion report по `testing/references/TASK_REPORT_TEMPLATE.md`: точный SHA, PR, tests/CI, инварианты, баги, privacy, ограничения. Только после его завершения переходить к следующему T.
