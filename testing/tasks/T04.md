# T04 — Telegram link taxonomy, identity and username churn

**Репозиторий:** teloxide-antispam + NedoBot. **Зависимость:** T03. **Тип:** implementation + actual tests, не просто план.

**Перед стартом:** прочитать актуальный `AGENTS.md` и соответствующий production/test код, `testing/references/INVARIANTS.md`, `testing/references/VALIDITY_LEVELS.md`, `testing/references/CORPUS_PRIVACY.md`. Начинать от свежего `main`, не использовать старые PR head. Работать офлайн на синтетике и тестовых БД.

## Cases
- `@name`, `t.me/name`, `tg://resolve?domain=...`, `tg://user?id=...`, native numeric text mention, channel message links `t.me/c/...`, invite hashes, `start`/`startgroup`/`startapp`/Mini Apps.
- Locally known bots, nonbots with bot-like suffix, aliases ending in `bot/agent/ai/app/game/gay`, username reassignment, stale and duplicate snapshots, affiliated channels, malformed peer IDs.
## Oracles
- Known unambiguous fresh alias maps to same numeric peer as native mention; stale or duplicate alias -> `Unresolved` and never wrong old ID.
- Numeric UserId and channel/chat IDs never conflated; bot suffix alone doesn't set `is_bot`; unresolved never treated as known external.
- No message-triggered external `getChat` lookup and no data passed to outside API; bounded only configured refresh.
## Acceptance
- Stateful alias-churn test over two owners and stale snapshots; negative tests for invite guessing, BotStart token redaction.
- Parser-only taxonomy tests in antispam, resolver DB tests in NedoBot, test pass counts >0.
