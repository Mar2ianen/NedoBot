# T12 — SQLite shared reputation: cross-process transactions and recovery

**Репозиторий:** NedoBot. **Зависимость:** T11. **Тип:** implementation + actual tests, не просто план.

**Перед стартом:** прочитать актуальный `AGENTS.md` и соответствующий production/test код, `testing/references/INVARIANTS.md`, `testing/references/VALIDITY_LEVELS.md`, `testing/references/CORPUS_PRIVACY.md`. Начинать от свежего `main`, не использовать старые PR head. Работать офлайн на синтетике и тестовых БД.

## Scenarios
- Two independent **OS processes** accessing same SQLite file, WAL and `BEGIN IMMEDIATE`, simultaneous spam/retraction, stale read, busy timeout, app restart, crash during transaction, disk error injection where feasible.
- NedoNews and PVO independent PG sources projecting into same SQLite ledger; test one active decision remains when other source retracts.
## Properties
- No lost updates or wrong source attribution; retractions per source and union semantics preserved. Restart sees durable decisions; WAL permissions and modes as specified.
- Cross-process recovery after process termination keeps journal valid. No JSON replacement or format migration.
## Acceptance
- At least one actual two-process integration test, distinct from two pools in one process; deterministic barrier between writers.
- Verify clean temp dir and never run tests against real `/var/lib/nedobot` paths.

1. Новый тест должен **сначала** воспроизвести ошибку или доказать ожидаемый инвариант; expected behavior не брать из проверяемой функции.
2. Оформить V1/V2/V3 для новых входов, оценить генерацию/отказы, сохранить воспроизводимый seed или минимальный trace.
3. Выполнить применимые `cargo fmt`, `cargo test`, `cargo check`, Clippy, feature matrix и интеграции с **ненулевым** числом тестов; для изменённых исполняемых путей показать доказательство из CI.
4. Не делать production deploy, Telegram API actions, изменения enforcement и работу с закрытым корпусом без доступа. Никаких сырых приватных данных в diff/логах/артефактах.
5. Написать `T12` completion report по `testing/references/TASK_REPORT_TEMPLATE.md`: точный SHA, PR, tests/CI, инварианты, баги, privacy, ограничения. Только после его завершения переходить к следующему T.
