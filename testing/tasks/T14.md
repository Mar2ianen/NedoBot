# T14 — Threat-feed safety, lookalike domains and network boundaries

**Репозиторий:** NedoBot. **Зависимость:** T13. **Тип:** implementation + actual tests, не просто план.

**Перед стартом:** прочитать актуальный `AGENTS.md` и соответствующий production/test код, `testing/references/INVARIANTS.md`, `testing/references/VALIDITY_LEVELS.md`, `testing/references/CORPUS_PRIVACY.md`. Начинать от свежего `main`, не использовать старые PR head. Работать офлайн на синтетике и тестовых БД.

## Cases
- Exact full URL hit vs domain hit vs substrings, expired feed, old revision, malformed feed, redirects in feed updater, very large response, unknown username or invite, shorteners, userinfo masquerading and punycode.
- Network mocked by local loopback/test transport; never follow historical-user URL or contact external service.
## Properties
- Only allowlisted feed updater endpoints are queried, with bounded download/redirect rules. Arbitrary URL cannot trigger SSRF, local host access or tracking third parties.
- Threat evidence does not automatically ban users; unknown targets aren't assigned verified reputation; feed freshness respected.
- Logging is redacted: request URLs, query auth and invite tokens absent.
## Acceptance
- Full offline mock HTTP suite including timeout, oversized response and redirect attempt; assert zero unexpected outgoing requests.
- Test feed exact lookup semantics against independent golden fixtures and TTL transitions.

2. Оформить V1/V2/V3 для новых входов, оценить генерацию/отказы, сохранить воспроизводимый seed или минимальный trace.

4. Не делать production deploy, Telegram API actions, изменения enforcement и работу с закрытым корпусом без доступа. Никаких сырых приватных данных в diff/логах/артефактах.
