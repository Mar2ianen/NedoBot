# T09 — Niri-style independent state machine and shrinking

**Репозиторий:** NedoBot. **Зависимость:** T08. **Тип:** implementation + actual tests, не просто план.

**Перед стартом:** прочитать актуальный `AGENTS.md` и соответствующий production/test код, `testing/references/INVARIANTS.md`, `testing/references/VALIDITY_LEVELS.md`, `testing/references/CORPUS_PRIVACY.md`. Начинать от свежего `main`, не использовать старые PR head. Работать офлайн на синтетике и тестовых БД.

## Implementation
- Write minimal in-memory reference model independent of production resolver/URL parser/shadow projection; define states per `(instance/chat/user/msg)` with current text, media generation, last resolved peer and expected evidence.
- Generate operation sequences `SaveMessage/Edit/IncomingDuplicate/ClaimQr/CompleteQr/Retry/Cancel/ObserveUsername/ObserveMembership/RefreshFeed/RefreshShadow/RestartWorker`; `DeleteStoredMessage` is local DB simulation, not Telegram Update.
- Model expected value after quiescence (leases drained); compare DB evidence, shadow fingerprint, risk invariance to a reference outcome. Shrink ops and payloads.
## Properties
- Same sequence seed reproducible; repeated edits do not accumulate stale evidence; obsolete QR completion not resurrected; source-neutral scoring.
- URL shadow never changes enforcement output. All user actors isolated.
## Acceptance
- At least 3 synthetic regression traces for historical failure classes; random tests in fast PR, larger long lane.
- At least one intentionally faulty oracle/implementation condition demonstrably detected; no shared production helper in expected side.
