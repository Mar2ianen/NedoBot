# T07 — QR/media synthetic image grid and resource bounds

**Репозиторий:** NedoBot / crates/nedobot-qr. **Зависимость:** T06. **Тип:** implementation + actual tests, не просто план.

**Перед стартом:** прочитать актуальный `AGENTS.md` и соответствующий production/test код, `testing/references/INVARIANTS.md`, `testing/references/VALIDITY_LEVELS.md`, `testing/references/CORPUS_PRIVACY.md`. Начинать от свежего `main`, не использовать старые PR head. Работать офлайн на синтетике и тестовых БД.

## Generate
- Embed a synthetic QR payload in white/noisy screenshots at varied size/position, with inversion, contrast, nearest-neighbor downscale, JPEG compression, rotation/cropping, multiple QR and duplicates.
- Separate intentionally corrupted/oversized images from known-decodable profile cases; support only formats currently decoded and do not claim video/GIF support unless implemented.
## Properties
- Correct payload extraction on documented decodable grid, repeated QR dedup, two distinct URL case variants remain distinct.
- Enforce compressed bytes, dimensions, pixels, aggregate scan pixels, candidate count, result count, payload length and bounded execution. Test just below/above each limit.
- No data exfiltration or logging of raw QR payload in error paths.
## Acceptance
- Reproducible grid summary successes and false negatives, synthetic media only; standalone decoder and parser integration.
- Establish benchmark environment and baseline without asserting arbitrary performance thresholds.

4. Не делать production deploy, Telegram API actions, изменения enforcement и работу с закрытым корпусом без доступа. Никаких сырых приватных данных в diff/логах/артефактах.
