## Cases
- Two isolated PG databases, overlapping synthetic chat/user/message IDs and same URL hashes, differing moderator labels, instance IDs and channel routes.
- Snapshot paths: SQL evidence, URL inventory, profile refresh, shadow, shared reputation, public/internal MCP.
## Properties
- No cross-instance leak of message content, private URL, operator label or read-model privileges. Shared SQLite ledger only shares intended `(instance_id,user_id)` decisions and not private messages.
- Default external/LLM read paths never acquire private URL evidence or raw invite tokens.
## Acceptance
- Existing two-DB MCP and role integrations extended with URL-specific synthetic fixtures. Test read-only role's negative permissions.
- Verified exact queries and filters; no globally shared per-process mutable state leaking across instances.
