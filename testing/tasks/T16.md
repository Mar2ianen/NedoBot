# T16 — Mutation, coverage, extended CI and reproducible triage

**Репозиторий:** teloxide-antispam + NedoBot. **Зависимость:** T15. **Тип:** implementation + actual tests, не просто план.

**Перед стартом:** прочитать актуальный `AGENTS.md` и соответствующий production/test код, `testing/references/INVARIANTS.md`, `testing/references/VALIDITY_LEVELS.md`, `testing/references/CORPUS_PRIVACY.md`. Начинать от свежего `main`, не использовать старые PR head. Работать офлайн на синтетике и тестовых БД.

## Implementation
- Add `cargo-llvm-cov` and targeted `cargo-mutants` selection for URL/Telegram classification, redaction, resolver, QR stale generation and PG lock paths. Detect intentionally inverted conditions; don't chase arbitrary percentage.
- PR fast lane (small deterministic proptest), nightly long lane (long random traces, fuzz), opt-in weekly mutation/performance. Budget and failure artifacts separated; no private corpora in Actions.
- Verify `#[ignore]` integration tests are actually invoked with `--ignored` and exact command, with positive nonzero count. Include logs and metadata-only crash triage, seed/corpus hash, V1/V2/V3 counts.
- Provide one command that reproduces a minimized failure from a task report on a disposable environment, and a stable source of observed regressions.
## Acceptance
- Show at least one intentionally injected mutation killed by a substantive assertion and one previously-uncovered meaningful branch covered.
- Re-run known regression seeds twice with identical result, PR and nightly workflows green; no user data exported.
- Final report enumerates tasks, confirmed bugs, behavioral divergences, false positives, performance limits and deliberately out-of-scope cases.

## Общая проверка и сдача

1. Новый тест должен **сначала** воспроизвести ошибку или доказать ожидаемый инвариант; expected behavior не брать из проверяемой функции.
2. Оформить V1/V2/V3 для новых входов, оценить генерацию/отказы, сохранить воспроизводимый seed или минимальный trace.
3. Выполнить применимые `cargo fmt`, `cargo test`, `cargo check`, Clippy, feature matrix и интеграции с **ненулевым** числом тестов; для изменённых исполняемых путей показать доказательство из CI.
4. Не делать production deploy, Telegram API actions, изменения enforcement и работу с закрытым корпусом без доступа. Никаких сырых приватных данных в diff/логах/артефактах.
5. Написать `T16` completion report по `testing/references/TASK_REPORT_TEMPLATE.md`: точный SHA, PR, tests/CI, инварианты, баги, privacy, ограничения. Только после его завершения переходить к следующему T.
