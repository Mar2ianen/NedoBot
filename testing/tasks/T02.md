# T02 — Two-chat historical URL corpus: privacy and provenance

**Репозиторий:** NedoBot only. **Зависимость:** T01. **Тип:** implementation + actual tests, не просто план.

**Перед стартом:** прочитать актуальный `AGENTS.md` и соответствующий production/test код, `testing/references/INVARIANTS.md`, `testing/references/VALIDITY_LEVELS.md`, `testing/references/CORPUS_PRIVACY.md`. Начинать от свежего `main`, не использовать старые PR head. Работать офлайн на синтетике и тестовых БД.

## Implementation
- Build **opt-in read-only local** extractor for NedoNews + PVO history using the actual per-instance Postgres configurations, with explicit authorization check. No calls to Telegram or URL destinations; if access absent, complete using two synthetic fixture databases and report no real coverage.
- Parse raw stored message entities and existing hash-only QR evidence. Preserve source and inability to recover QR URL from SHA. Do not infer missing URLs. Include `message_id` only in local private metadata.
- Normalize into a **private** test manifest: canonical URL identity, class, source, observed date, label provenance; separate two chats and cross-instance comparisons. HMAC-keyed pseudonyms only where stable identity needed, not unsalted hashes for public outputs.
- Make synthetic public corpus via transformation/hand-authoring, verify that transformed values are no longer personally identifying. No raw chat exports in repository or CI.
- Add corpus schema version and validator that rejects unexpected raw URLs/tokenlike strings in public cases (heuristic alone is insufficient; human privacy review).
## Acceptance
- Synthetic twin-DB extraction + pipeline works without network; private path 0700 / files 0600.
- Output counts with V1/V2/V3 metadata and collisions; real data processing explicitly gated, not assumed.
- No copied user text, actual invite hashes, numeric user IDs or secrets in diff, logs, artifacts.
