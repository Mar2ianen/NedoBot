# Задание для Codex: 16 последовательных задач по adversarial testing

Используй `$telegram-input-hunter`. Прочитай `AGENTS.md`, `testing/README_TASKS.md`, `testing/references/INVARIANTS.md`, `testing/references/VALIDITY_LEVELS.md` и первый файл задачи `testing/tasks/T01.md`.

Цель: создать в NedoBot воспроизводимый генеративный и model-based контур тестирования, который находит **входы, реально допустимые Telegram Bot API или явно помеченные как не подтверждённые**, нарушающие логику бота. Делай T01→T16 последовательно. Не прыгай вперёд и не объединяй всё в один большой PR. Если работа по задаче занимает много коммитов, разбивай её на небольшие PR без нарушения последовательности.

В начале каждого задания: обнови `main` двух репозиториев, проверь текущие API/инварианты и именование типов. Pure parser тесты живут в `Mar2ianen/teloxide-antispam/crates/teloxide-url` с соблюдением англоязычного AGENTS.md; DB/event интеграции и QR — в NedoBot.

Не выполняй сетевые запросы по пользовательским URL. Не обращайся к production Telegram, рабочим Postgres/SQLite, внешним чатам или чужим сервисам. Приватную историю двух чатов можно **читать только после отдельного подтверждения доступа и правил хранения**; если доступа нет, полностью закрывай задачу на синтетике, явно отметив частичное покрытие приватного корпуса. Сырые данные запрещено коммитить, логировать, прикладывать к CI или GitHub.

Для каждого обнаруженного дефекта: выбрать инвариант → указать V1/V2/V3 → получить воспроизводимый synthetic/minimized input, seed и trace → показать падающий тест на старом коде → исправить минимально → выполнить feature matrix + relevant integration tests + CI → зафиксировать отчет. Произвольное ослабление поведения или отключение check-ов не принимается.

Для каждой задачи прислать: PR, SHA, перечень тестовых целей/инвариантов, количество реальных запусков (>0), число valid/rejected generated samples, найденные и отклонённые случаи, минимальную безопасную регрессию, CI URL, приватность, оставшиеся риски. Нельзя считать green CI доказательством запуска теста, не посмотрев `test result`.

**Прямо сейчас начни T01.** После выполнения её acceptance gates и подтверждённого CI продолжай T02; последовательно закрой все T01..T16. Нет разрешения на продакшен-деплой, изменение enforcement и работу с боевыми БД.
