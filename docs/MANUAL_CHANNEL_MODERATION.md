# Ручная блокировка отправки от имени канала

После отдельного обновления бинарника и additive migration
`20261120200000_manual_sender_chat` администратор может ответить на комментарий
канала командой `/ban` или `/unban`. Необязательная причина: `-- причина`.
Доступен только reply в том же модерируемом чате, без числовой цели и срока.
Администратор и бот должны иметь право ограничивать участников.

NedoBot использует уже существующие typed методы форка teloxide:
`ban_chat_sender_chat` / `unban_chat_sender_chat`. Raw HTTP и изменения fork
не нужны. Telegram-адаптер проверяет `sender_chat` до `from`: технический
`Channel_Bot` не является личностью администратора канала. Ник не используется
как identity. Анонимные администраторы самого чата и исходные auto-forward
посты не становятся целями этой команды. Для них отказ, без fallback на user ban.
Сам контент и принадлежность каналу сохраняются.

Согласно [Telegram Bot API](https://core.telegram.org/bots/api#banchatsenderchat),
пока канал заблокирован, его владелец не может писать в этом чате от имени
любых своих каналов. Это семантика Telegram, а не поиск личного аккаунта.
Команда блокирует/разблокирует отправку средствами Telegram. Она не
банит найденного по догадке владельца, не меняет account spam labels, не удаляет
историю канала, не включает автобаны и не заменяет капчу человеку. Unban не
обещает восстановить иные ограничения Telegram. `/undo` и `/modlog` пока
работают с пользовательским журналом; для каналов используется отдельный
приватный `manual_sender_chat_operations`.

Перед внешним вызовом команда сохраняется с actor, chat, source message,
channel ID, действием и причиной. Общий lock с пользовательским журналом
не позволяет edited update переключить тип цели, параллельные команды одного
канала блокируются. Повтор того же update после ack не повторяет API-вызов.
Timeout, crash или неподтверждённый ответ оставляют `started`/`unknown`;
автоматического retry нет. Это блокирует дальнейшие команды этой цели до
операторской сверки Telegram и журнала. В таком случае доступен ручной
разбан через интерфейс Telegram; бот не выдаёт неизвестный исход за успех.

Вывод следует короткому результату модерации из CARD_STYLE:
«Отправка сообщений от этого канала в чате заблокирована» /
«Блокировка отправки сообщений от этого канала в чате снята».
Ответ доставляется существующим helper и сохраняет настроенную аудиторию.

Production-конфигурация, миграции production и Telegram-состояние в рамках
разработки не изменяются. Действия проверяются только через disposable PG и
локальный Telegram stub. Канальные сообщения не получают личный ID-риск,
аватарный аудит и капчу proxy-аккаунта. Проверка содержания каналов и новые
автоматические правила остаются отдельной областью и здесь не включаются.
