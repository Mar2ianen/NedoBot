# Данные о ссылках Telegram

Крейт `teloxide-url` ограниченно извлекает URL и ссылки Telegram из видимого
текста, нативных Telegram entities и поддерживаемых блоков `RichMessage`.
Он не обращается к сети и не принимает решений о модерации. NedoBot сохраняет
историческую семантику `has_links`; `link_count` и `link_count_24h` по-прежнему
считают сообщения, а не отдельные URL.

Для последнего сообщения со ссылкой в окне аудита новичка отпечаток содержит
версионированный дайджест видимого текста и нормализованных URL. Derived
evidence хранит SHA-256 цели, host, тип, источник (видимый текст, Telegram
entity, RichMessage или QR), privacy-флаг и подсказку без пути, query или токенов
приглашений. Отдельная запись runs хранит версию парсера и fingerprint
исходного сообщения, включая сообщения без ссылок. Изменение скрытой цели
меняет fingerprint даже при прежнем видимом тексте и ID сообщения.

Для старых строк есть ограниченный dry-run/apply: `cargo run --bin
backfill_url_evidence -- <chat-id> --limit 500` считает кандидатов; добавление
`--apply` записывает derived evidence. Продолжение задаётся через
`--after <message-id>`. Backfill не меняет сообщения, метки или задания аудита.

`url_relations` связывает явные числовые ID и usernames только со свежими
локальными Telegram-снимками. `telegram_username_aliases` индексирует текущие
основные и дополнительные имена с типом peer, источником и временем наблюдения;
смена имени деактивирует старые aliases. Неоднозначные совпадения нескольких
peer и снимки старше 24 часов fail closed. Активные имена профилей обновляются
при плановом profile refresh, а настроенные каналы, подтверждённые связанные
чаты и ограниченная очередь известных ботов обновляются фоновым Bot API
refresh по numeric ID. На каждое сообщение сеть не вызывается. ID связанного
чата добавляется только после успешной проверки через Bot API. Неизвестные
приглашения остаются неразрешёнными; статус членства не запрашивается отдельно
для каждой ссылки.

Опциональный `moderation.url_feed_enabled` загружает только официальный
`Phishing.Database/phishing-links-ACTIVE.txt` и его commit metadata с GitHub.
Список заявлен под MIT; snapshot не хранится в репозитории и не раздаётся через
MCP. В конфигурации отдельно задаются `url_feed_refresh_seconds` (1–24 часа) и
`url_feed_max_age_seconds` (1 час–30 дней; рекомендуем 7 дней). Возраст считается
по времени upstream-коммита, а не скачивания. Если источник устарел или загрузка
не прошла лимиты/проверки, предыдущая версия остаётся в памяти, но stale snapshot
не даёт совпадений. Редиректы отключены; фиксированный updater никогда не
получает URL из сообщений.

Feed сравнивает нормализованные точные URL. Путь и query не расширяются до
домена, чтобы не сделать широкую блокировку. Для QR используется тот же
versioned SHA-256 fingerprint, поэтому распознанный адрес не раскрывается
повторно. Upstream строки с неподдерживаемыми схемами и malformed данными
отбрасываются; загрузка целиком отклоняется при слишком большом объёме,
недостаточном количестве корректных записей или высокой доле ошибок.

`teloxide-antispam::url_shadow` принимает структурированные URL evidence и
возвращает отдельную объяснимую advisory-сумму. NedoBot записывает её только в
unified audit snapshot. Она не меняет действующий baseline score, Decision,
капчу, review или блокировку; свежий feed hit сам по себе не является поводом для
санкции. URL списка не отправляются внешнему сервису репутации.

Опциональный `qr_evidence_enabled` подключает `nedobot-qr` к очереди Telegram:
фотографии, image-документы и статичные WebP-стикеры модерируемых чатов
обрабатываются одним фоновым worker. Скачивание ограничено 5 MiB и 120 секундами;
декодирование вынесено в `spawn_blocking`, с лимитами сторон/пикселей/числа кодов.
Результат сохраняет только отпечаток URL и host, никогда сырой payload или URL.
Для QR-ссылки дополнительно сохраняется безопасная метка `affiliated`, `external`
или `unresolved`: собственные чаты и настроенные связанные каналы не считаются
внешними. Имя канала по URL разрешается только по текущему однозначному alias;
неизвестный или конфликтующий Telegram username остаётся `unresolved`. Lease и текущий `file_unique_id` перепроверяются в транзакции перед
записью, поэтому результат отредактированного медиа отбрасывается. Ошибка
обновления URL-shadow переводит задачу в существующую очередь retry с backoff;
параллельные пересчёты одного процесса сериализуются, а между процессами — через
PostgreSQL advisory lock. При удалении сообщения дочерние jobs и evidence
удаляются по FK. Флаг выключен по умолчанию и не включает scoring, капчу, review
или блокировку. Анимация, TGS, видео и OCR не входят в этот этап; скорость на
реальных скриншотах ещё предстоит измерить.

Одни лишь признаки URL не меняют оценку, капчу, очередь проверки или правила
блокировки. Включать оценку можно после повторной проверки на человеческих
метках, разделённых по авторам и кампаниям, с отчётом о precision, recall и
ложных срабатываниях относительно текущей модерации.
