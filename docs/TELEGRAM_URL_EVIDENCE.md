# Данные о ссылках Telegram

Крейт `teloxide-url` ограниченно извлекает URL и ссылки Telegram из видимого
текста, нативных Telegram entities и поддерживаемых блоков `RichMessage`.
Он не обращается к сети и не принимает решений о модерации. NedoBot сохраняет
историческую семантику `has_links`; `link_count` и `link_count_24h` по-прежнему
считают сообщения, а не отдельные URL.

Для последнего сообщения со ссылкой в окне аудита новичка отпечаток содержит
версионированный дайджест видимого текста и нормализованных URL. Derived
evidence хранит SHA-256 цели, host, тип, источник (видимый текст, Telegram
entity, RichMessage или QR), privacy-флаг и подсказку без пути, query или токенов
приглашений. Отдельная запись runs хранит версию парсера и fingerprint
исходного сообщения, включая сообщения без ссылок. Изменение скрытой цели
меняет fingerprint даже при прежнем видимом тексте и ID сообщения.

Для старых строк есть ограниченный dry-run/apply: `cargo run --bin
backfill_url_evidence -- <chat-id> --limit 500` считает кандидатов; добавление
`--apply` записывает derived evidence. Продолжение задаётся через
`--after <message-id>`. Backfill не меняет сообщения, метки или задания аудита.

`url_relations` связывает только явные числовые ID с известным статусом
членства и настроенными маршрутами каналов и чатов обсуждений. ID связанного
чата добавляется только после успешной проверки через Bot API. Username, хеш
приглашения и недоступный API остаются неразрешёнными. Статус членства не
запрашивается отдельно для каждого сообщения.

Локальное сопоставление со списками пока не подключено ни к загрузчику, ни к
самому feed. Сторонние списки URL не распространяются, исходные пользовательские
URL не отправляются внешним сервисам репутации. До включения списка нужно
зафиксировать источник, лицензию, ревизию, срок актуальности и условия
распространения.

Опциональный `qr_evidence_enabled` подключает `nedobot-qr` к очереди Telegram:
фотографии, image-документы и статичные WebP-стикеры модерируемых чатов
обрабатываются одним фоновым worker. Скачивание ограничено 5 MiB и 120 секундами;
декодирование вынесено в `spawn_blocking`, с лимитами сторон/пикселей/числа кодов.
Результат сохраняет только распознанные URL как QR-derived evidence, никогда не
сырой payload. Lease и текущий `file_unique_id` перепроверяются в транзакции перед
записью, поэтому результат отредактированного медиа отбрасывается. При удалении
сообщения дочерние jobs и evidence удаляются по FK. Флаг выключен по умолчанию и
не включает scoring, капчу, review или блокировку. Анимация, TGS, видео и OCR не
входят в этот этап; скорость на реальных скриншотах ещё предстоит измерить.

Одни лишь признаки URL не меняют оценку, капчу, очередь проверки или правила
блокировки. Включать оценку можно после повторной проверки на человеческих
метках, разделённых по авторам и кампаниям, с отчётом о precision, recall и
ложных срабатываниях относительно текущей модерации.
