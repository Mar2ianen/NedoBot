# Аудит /ask и подготовка релиза, 6 октября 2026

Проверены сохранённые запросы за 5 октября: 30 запусков, 28 завершённых,
два `generation_error`. Оба сбоя в journal оказались HTTP 402. Приватные
вопросы, сообщения, ответы и выгрузка аудита в репозиторий не включены.

## Контекст и инструменты

- Rich-ответы теряли текст и в `telegram_messages`, и в непосредственном
  reply-контексте. Общая typed-проекция теперь читает вложенные текстовые
  блоки, таблицы, подписи, ссылки и custom emoji. Thinking, callback data,
  file IDs и неизвестные wire-объекты в текст не включаются.
- В production обнаружены 152 rich-сообщения без текстовой проекции.
  `backfill_rich_messages` восстанавливает их из native payload, по одному
  явно выбранному чату. По умолчанию dry run; update проверяет исходный
  payload и не перезаписывает уже заполненный текст.
- Telegram передаёт только один уровень reply. Агент теперь предварительно
  загружает bounded контекст через scoped MCP и записывает вызов в аудит.
  Связь ответа с командой сохраняется и при rich edit, и при HTML/file fallback.
- Настройка чата для личных запросов ошибочно применялась к группам.
  Групповой `/ask` теперь использует свой чат. Личный режим остаётся scoped
  к настроенному default chat.
- Счётчик сообщений выдавался за число употреблений слова. Новый
  `chat.count_word_occurrences` считает неперекрывающиеся вхождения точного
  слова/фразы, включая повторения внутри одного сообщения. Границы regex
  не потребляют разделители; фильтры и chat scope общие со счётчиком сообщений.
- Перед текстовым count runtime требует успешный поиск с тем же полным
  scope. Смена автора, периода, match mode или forward-фильтра требует
  нового поиска. `count` и его единица сохраняются в аудите и контексте.
- Native history больше не дублирует все tool results на каждом шаге.
  Старые завершённые пары удаляются целиком; исходный вопрос, последний
  виток и проверенные счётчики сохраняются. Размер previews ограничен и
  для нескольких одновременных tool calls. Полная история передаётся без
  provider-specific continuation ID.
- После action timeout повтор начинается со следующего совместимого
  profile. `ask_runs` сохраняет фактически ответивший provider/model и
  количество model turns; завершение больше не обнуляет turns без tools.
- При занятом слоте команда получает понятный ответ вместо тихой IO-ошибки.
  Политика `delivery_unknown` сохраняется: повторная отправка запрещена.

## Задания и качество ответов

Проверены задачи поиска участников и профилей, продолжения диалога,
подсчёта слов, оценки споров, roleplay и вопросов по постам с фотографиями.
Основные повторяющиеся ошибки: потеря rich-контекста, недостаточный контекст
reply, подмена единицы подсчёта и старые результаты вместо текущего спора.
Правила вынесены в `prompts/ask.md`: persona не заменяет проверку фактов;
при недостатке контекста следует перечитать thread/context.

У всех сохранённых запусков старше часа на момент проверки был конечный
статус: зависших `running`/`delivery_pending` не обнаружено. Diagnostic replay
не сохраняет заметки и не отправляет сообщения в Telegram.

В `agent-runtime` исправлены разрыв причинной пары при compaction,
игнорирование недостижимого бюджета, удаление части mandatory pair,
отмена родителя через child token и происхождение пустого usage. В CI
включён весь workspace. Это набор примитивов; generic executor и durable
session store ещё не подключены к боту. Оценка токенов L0 эвристическая.

## Другие исправления предыдущего ревью

- Репутационные признаки передаются по именам из artifact: Gemma и TF-IDF
  перестали менять местами. `has_text` берётся из фактического текста;
  отсутствующий behavior snapshot выключает этот supporting signal.
  Неизвестные признаки отклоняются на старте. Версия materialization — v8.
- Миграция повторяет только derived materialization успешных v7 assessments,
  без нового LLM-аудита; старые CAS claims инвалидируются сменой версии.
- Legacy Groq ASR profile больше не включает Gemini shadow по умолчанию.
  Для Gemini primary video notes направляются в настроенный Groq media
  fallback независимо от сравнительного shadow flag; его key валидируется.
- ASR ошибки очищаются от upload URL; ограничены общий Gemini deadline и
  cleanup. Поддержан ответ `outputs` без поля `steps`.
- Рекламный marker проверяется в полном посте до удаления подписи.
- Retention использует настоящую первую дату сообщения: старый участник
  после паузы больше не становится новым cohort.
- Release installs используют lock, уникальные temp dirs и preflight всех
  файлов. GitHub release runs сериализованы; production deploy требует
  commit, слитый в main. Название артефакта содержит SHA собранного source.

## Проверки

`cargo fmt --all`, workspace tests, Clippy с `-D warnings`; отдельная БД
PostgreSQL для миграций, public scope, counts, retention, backfill, job CAS
и replay; RMCP child test; manual moderation tests; concurrent installer
и отсутствие частичной замены при неполном stage. Native HTTP mock проверяет
переход к следующему profile после timeout и правильную запись его identity.

Дополнительно с VPS проверены API: OpenRouter text fallback вернул 200,
Gemini vision fallback вернул 200 и native function call. Прямой Python HTTP
probe Groq получил 403; для проверки именно SDK в артефакте есть
`probe_ask_route [--image]`, без Telegram и доступа к БД.

Production не перезапускался. Выкладка и backfill описаны в `DEPLOYMENT.md`.
