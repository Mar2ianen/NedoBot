# Анализ URL и Telegram-целей

URL shadow остаётся наблюдательным сигналом. Он не меняет production scoring,
captcha, review или ban. Видимые URL, Telegram entities, RichMessage и QR
сопоставляются по канонической цели; источник хранится только как provenance.

## История ссылок

Администратор может выгрузить историю чата в JSONL:

```bash
cargo run --bin export_url_inventory -- \
  --chat-id <CHAT_ID> \
  --format jsonl \
  --redact-secrets \
  --output links.jsonl
```

Экспорт читает сообщения курсорами по всей сохранённой истории и ограничивает
объём агрегирования 100 000 целями и 1 000 000 парами «цель—сообщение».
При превышении лимита экспорт завершается ошибкой вместо выдачи неполного
результата. Результат формируется во временном файле в каталоге назначения с
правами `0600` и атомарно заменяет итоговый файл только после успешной записи и
синхронизации на диск. Для каждой цели выводятся SHA-256 fingerprint полного
канонического URL и безопасная отображаемая версия: query, fragment и секреты
не попадают в открытый текст. Поэтому разные query-варианты не склеиваются при
агрегации. Для целей и хостов выводятся число сообщений, авторов, временные
границы, количество авторов с текущим `is_spammer` и число авторов по последней
метке `spam/not_spam` источников `owner_review`, `owner_manual` или
`legacy_backfill` (системные события не перезаписывают это значение), а также
источники извлечения. Поле
`resolution=Unresolved` означает, что экспорт сам не выполняет сетевое
разрешение цели.

Query, fragment и userinfo удаляются; Telegram invite hash скрывается. По
умолчанию весь непустой URL path заменяется на `/<redacted-path>`, поскольку
короткий сегмент тоже может быть токеном. Для локальной административной
диагностики можно явно добавить `--show-paths`; эта опция может раскрыть секрет
в произвольном path. Query, fragment, userinfo и invite hash остаются скрыты
при обоих режимах. Файл всегда создаётся с правами `0600`. QR evidence хранит
только SHA-256 и безопасный
display hint. Из хеша нельзя восстановить ссылку, поэтому экспорт отмечает
такие строки как `qr_target_unrecoverable`; он не угадывает исходный URL.
Для восстановления QR-целей требуется отдельный bounded повторный анализ
доступных Telegram media, который здесь не запускается.

QR и URL evidence дедуплицируются после общего URL parser: hostname
нормализуется, а регистр path и query сохраняется. Это не объединяет URL,
которые сервер может трактовать как разные ресурсы.

Обновление URL shadow сериализуется per instance/chat/user одним PostgreSQL
advisory lock для QR/edit refresh и профильного аудита. Блокировка охватывает
чтение evidence и запись результата; разные пользователи обновляются независимо.

Сводка сейчас агрегируется по полному host. Registrable-domain группировка
требует зафиксированной версии Public Suffix List и пока не включена. В базе
нет подтверждённых normal-labels для всех авторов; поэтому экспорт показывает
число известных spam-авторов, а не считает остальных нормальными.

## Локальный resolver

Профиль Telegram/mention/message ссылки сначала разбирается локально. Числовой
Telegram ID и username разрешаются только по локальным снимкам; сетевой lookup
по пользовательской ссылке не выполняется. Username считается кандидатом на
бота при суффиксах `bot`, `agent`, `ai`, `app`, `game`, `gay`, но это не
подтверждает `is_bot`: подтверждением служит только сохранённый Telegram
профиль. Для username требуется ровно одна запись с наблюдением не старше
24 часов. Исторические identity snapshots не используются для владения
именем, потому что Telegram может назначить его другому аккаунту. Неизвестные,
устаревшие и неоднозначные цели остаются `Unresolved`.

Собственные/связанные каналы определяются из конфигурации маршрутов и свежего
Bot API снимка `linked_chat_id`. Invite hashes, неразрешённые usernames,
Bot Start и Mini App payloads сохраняются без передачи третьим сторонам.

## Внешние feeds

Единственный подключённый источник — opt-in [Phishing.Database](https://github.com/Phishing-Database/Phishing.Database).
Его README указывает MIT License и предоставляет отдельные активные URL feeds.
Совпадение остаётся evidence, а не решением о блокировке.

URLhaus не подключён: [официальные условия использования](https://abuse.ch/terms-of-use/)
ограничивают бесплатное
использование fair-use объёмами, требуют аутентификации и допускают отдельную
подписку для коммерческого/for-profit применения. Перед интеграцией нужно
подтвердить подходящий тип использования и лимиты аккаунта. Списки uBlock не
подключены: лицензия проверяется для каждого списка отдельно; сам
[репозиторий uAssets](https://github.com/uBlockOrigin/uAssets) GPL-3.0, а
[каталог лицензий uBlock](https://github.com/gorhill/uBlock/wiki/Filter-list-licenses)
отмечает у разных списков GPL, CC0, CC BY,
non-commercial и неопределённые условия. Общий парсер Adblock также не нужен
для URL reputation без отдельной проверки формата и лицензии конкретного
источника.

Произвольные URL пользователей не запрашиваются. Redirect expansion и
shortener resolution требуют отдельного SSRF/DNS-rebinding защищённого
механизма и остаются вне основного пути.

## QR

QR сканируется в пределах заданного бюджета пикселей и числа кандидатов:
оригинал, инверсия, ограниченные перекрывающиеся области и увеличенные угловые
области. Найденные строки поступают в тот же `teloxide-url` parser, что и
обычные источники. Анимированные GIF/video stickers не обрабатываются.
